# PortScan — Android

Первая версия приложения для чтения номеров контейнеров камерой. Видео нужно в том числе для обхода изогнутой поверхности: номер собирается из перекрывающихся фрагментов, даже если целиком не попал ни в один кадр.

## Установка

Собранный APK: [PortScan-debug.apk](artifacts/PortScan-debug.apk). Android 8.0 и новее. Это тестовая сборка с отладочной подписью, не релиз для Google Play.

Передайте APK на телефон и откройте его. Разрешите установку из выбранного источника, затем предоставьте PortScan доступ к камере. Модель включена в APK. Интернет и аккаунт не требуются; разрешение на доступ к интернету удалено из итогового манифеста.

## Как снимать

1. Нажмите **Новый проход** перед каждым следующим контейнером.
2. Наведите камеру на начало номера, включая буквенный префикс. Нажмите на изображение для фокусировки.
3. Медленно перемещайтесь вдоль поверхности. В соседних ракурсах должны повторяться хотя бы **три читаемых символа**. Держите телефон ровно, избегайте бликов и смаза.
4. Номер на экране заполняется по мере поступления фрагментов. Точки обозначают ещё не прочитанные позиции.
5. Для сохранения исходного материала нажмите **Видео** или **Серия**. Видео пишется без звука; серия снимает до 60 фотографий с паузой после обработки каждого снимка. Исходные материалы доступны через **Записи**.
6. Проверьте полный номер. Нажатие на карточку копирует его, **CSV** сохраняет историю в выбранное место.

На устройствах, которые не поддерживают одновременные Preview + VideoCapture + ImageAnalysis, видео распознаётся после остановки записи. Во время записи приложение сообщает об этом.

**Фото / видео +** импортирует несколько материалов одного контейнера в новый проход. Последовательно декодируется по одному изображению; видео анализируется с шагом 200 мс. Можно отменить обработку, сохранив уже найденные номера. Несколько кадров не обязательно означают несколько независимых наблюдений: при малом FPS видео декодер может возвращать одинаковые кадры.

В истории объединяются одинаковые номера внутри одного прохода. История полных номеров сохраняется между запусками (до 1000 записей, затем приложение предлагает экспорт и очистку). Неполные фрагменты текущего прохода находятся в памяти и при завершении процесса теряются. Сохранённые фото и видео можно повторно распознать. Удаление приложения удаляет его внутренние записи; заранее поделитесь нужными материалами через **Записи**.

## Номер контейнера и проверка

Стандартная идентификация ISO 6346: **3 буквы владельца + U/J/Z + 6 цифр серийного номера + контрольная цифра**. Для грузовых контейнеров используется `U`. Например, `CSQU 305438 3`. Это четыре буквы и семь цифр, а не только цифры. [Описание BIC](https://www.bic-code.org/identification-number/), [контрольная цифра BIC](https://www.bic-code.org/check-digit-calculator/).

- **Контрольная цифра ✓** — совпала контрольная цифра ISO 6346. Это не проверка регистрации контейнера в реестре BIC.
- **Повторён** — каждый символ поддержан фрагментом, встретившимся как минимум в двух обработанных кадрах.
- **Из фрагментов** — весь номер не был прочитан одним OCR-регионом; проверьте его особенно внимательно.
- **Проверить контрольную цифру** — полный вариант сохранён, но контрольная цифра не совпадает.
- При нескольких вариантах приложение показывает конфликт и сохраняет варианты, а не выбирает один молча.

Прочие числовые надписи показываются в строке «Числа в кадре». В постоянную историю и CSV попадают полные контейнерные номера.

## Скорость и границы первой версии

- Нативные CameraX + ML Kit Text Recognition, встроенная латинская модель; кадры не отправляются на сервер.
- Камера передаёт YUV-буфер напрямую, без JPEG-кодирования в цикле распознавания.
- `KEEP_ONLY_LATEST`, один OCR-запрос за раз, ограничение запуска до 8 кадров/с. Это предел частоты запуска, а не обещанная скорость.
- Предпочтительное разрешение анализа 1280×720; CameraX выбирает поддерживаемое ближайшее. Для импортированных фото длинная сторона ограничена 1600 пикселями, для видео — 1280.
- На экране показаны время OCR и частота поступления результатов. Время OCR не включает съёмку, декодирование и отрисовку. Частота включает эти задержки между результатами.
- Состояние сборки ограничено 96 фрагментами и 128 вариантами. При достижении лимита показывается предупреждение. Повторяющиеся наблюдения используют закэшированный результат сборки.

Сборка — **текстовое совмещение перекрытий**, не восстановление 3D-поверхности. Она требует читаемых фрагментов и хотя бы одного кадра с полным четырёхбуквенным префиксом. Сильная кривизна, вертикальная маркировка, ржавчина, блики и сильный наклон могут помешать обычной OCR-модели. Геометрическое выпрямление и специализированная модель для контейнерной маркировки пока не реализованы.

Нельзя надёжно склеить части без перекрытия. Программа не придумывает пропущенную контрольную цифру и не заменяет автоматически `O/0`, `I/1`, `B/8`. Совпадение контрольной цифры не исключает ошибку OCR или соединение надписей разных объектов, поэтому один проход предназначен для одного контейнера. Несколько контейнеров в кадре не отслеживаются по отдельности. Пропускаемые кадры могут содержать единственный читаемый вариант: для быстрого движения нужна более медленная съёмка или повторный проход.

Скорость и точность на реальных портовых видео **ещё не измерены**. Для следующего этапа нужны записи реальных номеров и целевой Android-телефон.

## Сборка и проверки

JDK 17+ (проверено с 21), Android SDK Platform 36, Build Tools 36.0.0. Gradle Wrapper 9.3.1, Android Gradle Plugin 9.1.0. Версии зависимостей зафиксированы.

```sh
export JAVA_HOME=/path/to/jdk
export ANDROID_HOME=/path/to/android-sdk
sh scripts/build-local.sh
```

Скрипт запускает `testDebugUnitTest lintDebug assembleDebug`. В этом рабочем пространстве он также может использовать уже установленный toolchain из соседнего проекта. Исходный APK: `app/build/outputs/apk/debug/app-debug.apk`.

Тесты ядра проверяют контрольную цифру, сборку из двух/трёх ракурсов в разном порядке, повторное наблюдение, конфликтующие результаты, отсутствие недостающих символов, разделение проходов и пределы памяти. Они проверяют сборку OCR-текста, а не качество распознавания изображений.

Для проверки на устройстве: установите APK, отключите интернет, проверьте камеру, фокус, поворот экрана, паузу, отказ в разрешении, запись/остановку видео, серию фото, импорт, отмену и экспорт. Затем снимите минимум 20 контейнеров с известными номерами, включая криволинейные поверхности. Сравните долю правильно прочитанных полных номеров, ложные полные варианты, время до первого результата и время до полного номера. Отдельно проверьте нагрев при длительной работе.

Основные файлы: `MainActivity.java` — камера и интерфейс; `OcrEngine.java` — встроенная модель; `MediaReader.java` — последовательное декодирование; `core/ContainerAssembler.java` — объединение фрагментов; `core/ContainerCode.java` — контрольная цифра; `ScanHistory.java` — история и CSV.
